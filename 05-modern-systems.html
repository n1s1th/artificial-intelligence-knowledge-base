Modern AI Systems

How models become products: generative AI, agents, the AI system stack, hardware infrastructure, and the frameworks that make modern AI work in practice.

A useful AI product is usually more than its model.

A model is a component. A deployed AI system can add instructions, data access, retrieval, tools, memory, interfaces, monitoring, and evaluation. This note explains how generative AI, agents, and the full system stack transform machine learning models into practical applications.

01 — Generative AI

Systems that create new content.

Generative artificial intelligence (GenAI) is a subfield of AI that uses generative models to produce new content — text, images, audio, video, code, and other modalities — from learned patterns in training data.

Generative AI
AI systems capable of generating new outputs such as text, images, audio, video, or code from learned representations of training data, typically in response to natural-language prompts.

Multimodal models

Modern systems are increasingly multimodal — a single model can process and generate text, images, audio, and video. GPT-4o, Gemini, and Claude can accept images as input and produce text, while newer models can produce video from text prompts. This convergence is one of the most significant trends in modern AI.

02 — LLMs

Large language models: the backbone of modern AI.

Large language models (LLMs) are generative pre-trained transformers trained on massive text corpora. They have become the foundation of most modern AI products, from chatbots to code assistants to autonomous agents.

LLM
A large neural network based on the transformer architecture, pre-trained on vast text data to predict the next token in a sequence. LLMs exhibit emergent capabilities — abilities not explicitly trained but arising from scale.

Pre-training

The model learns language patterns, facts, and reasoning by predicting the next word in billions of text examples. This phase is extremely expensive (millions of dollars in compute) but produces a general-purpose language model.

Fine-tuning & RLHF

After pre-training, models are fine-tuned on curated data and aligned via reinforcement learning from human feedback (RLHF) to follow instructions, be helpful, and avoid harmful outputs.

Emergent capabilities and scaling laws

As models grow larger, they exhibit capabilities not present in smaller versions — solving complex reasoning, writing code, translating languages. This has driven a race to build ever-larger models, but the relationship between scale and capability is not fully understood, and returns may diminish.

03 — Agents

When a model becomes a goal-pursuing system.

AI agents are software entities designed to perceive their environment, make decisions, and take actions autonomously to achieve specific goals. An agent is more than a model — it is a model embedded in a loop of reasoning, tool use, memory, and action.

AI Agent
A system that uses a language model within a broader loop of perception, reasoning, tool use, state or memory, and action to pursue a goal through repeated interaction with an environment.
Figure 06 · The agent loop: an LLM reasons about a goal, takes actions through tools, observes results, and repeats until the goal is achieved

Tool use

Agents call external tools — web search, code interpreters, APIs, databases — to act on the world. This extends the model's capabilities far beyond text generation.

Memory

Agents maintain state across interactions: conversation history, retrieved documents, task progress. This allows multi-step reasoning and long-running tasks.

Autonomy

Agents can operate with minimal human oversight, breaking complex goals into subtasks and adapting when things go wrong. The degree of autonomy varies by design.

Agentic AI: the next frontier

Companies like OpenAI, Anthropic, and Google are investing heavily in agentic systems. Frameworks like CrewAI and OpenClaw enable multi-agent collaboration. The shift from single-turn chat to multi-step agents represents a fundamental change in how AI is deployed. → Note 06: Applications

04 — System stack

The layers between a model and a user.

When you encounter an AI application, ask two questions: "What model is being used?" and "What system has been built around it?" The second question often explains capabilities that a model alone cannot provide.

Figure 07 · The AI system stack — boundaries vary by implementation, but the layers are conceptually distinct

Retrieval-augmented generation (RAG)

Instead of relying only on a model's training data, RAG systems retrieve relevant documents from a knowledge base and include them in the prompt. This reduces hallucination and keeps answers grounded in current, verified information.

Guardrails & evaluation

Production systems add input filtering, output validation, toxicity detection, and continuous evaluation. These layers catch failures the model cannot prevent on its own. → Note 07: Ethics, Risks & Harms

05 — Infrastructure

The hardware that makes AI possible.

In the late 2010s, graphics processing units (GPUs) that were increasingly designed with tensor operations started to be used to accelerate neural networks, overtaking CPUs as the dominant platform for training and running AI models.

GPU
Graphics processing unit — originally designed for rendering graphics, GPUs excel at the parallel matrix multiplications that neural networks require, making them the primary hardware for AI training and inference.

The compute bottleneck

Training frontier models requires thousands of GPUs running for months, consuming megawatts of electricity and costing tens of millions of dollars. This creates a significant barrier to entry and concentrates AI development in well-funded organisations. → Note 07: Ethics (environmental impacts, tech giant dominance)

06 — Frameworks

The software that makes AI practical.

Modern AI depends on a rich ecosystem of open-source and commercial software that handles training, inference, deployment, and monitoring.

Training frameworks

PyTorch, TensorFlow, JAX — provide the primitives for building and training neural networks on GPUs and TPUs.

LLM tooling

Hugging Face Transformers, vLLM, Ollama, LangChain — make it practical to load, serve, and chain LLM calls together.

Agent frameworks

LangGraph, CrewAI, AutoGen, OpenClaw — orchestrate multi-step agent workflows with tools, memory, and planning.

Model serving

TensorRT-LLM, Triton, Ray Serve — optimise inference latency and throughput for production deployments.

Vector databases

Pinecone, Weaviate, pgvector, Qdrant — store and retrieve embeddings for RAG and similarity search.
